# IDENTIFIERS — the data-language spec for OpenEndo datasets

Every entity in OpenEndo data carries a **stable, resolvable identifier**
from the vocabulary the medical-research industry already uses. This is
the interoperability contract — tools (ELNs, LIMS, notebooks, knowledge
graphs) can join our data to theirs without custom glue.

## The table

| Entity | Identifier | Datasets | Status |
|---|---|---|---|
| clinical trial | `NCT####…` (+ ClinicalTrials.gov URL) | `trials_*.json` | ✅ |
| paper | `PMID` (+ PubMed URL) | `pubmed_*.json`, evidence weekly | ✅ |
| drug target | `CHEMBL####` + HGNC gene symbol | `targets.json` | ✅ |
| protein | UniProt accession | fold_input manifest | ✅ |
| drug/molecule | `CHEMBL####` | `targets.json`, `repurposing_candidates.json` | ✅ |
| funding call | source URL | `funding.json` | ✅ |
| chemical entity | `ChEBI####` | biomarker track | 🔜 |
| phenotype / concept | `HPO` / `MeSH` / `EFO` | evidence map topics | 🔜 |
| person | `ORCID` | contributors | 🔜 |
| organisation | `ROR` | `funding.json` | 🔜 |

## Rules

1. **Never invent an identifier.** Unknown → store the resolvable URL, mark
   `id_kind: "url"`, and note the gap.
2. **Keep the source identifier verbatim** — NCT/PMID/CHEMBL strings are
   copied exactly from the source API, never "normalized".
3. Every dataset record that references an external entity MUST carry its
   identifier + a resolvable URL (CONTRIBUTING.md: links verified HTTP 200).
4. Provenance fields (`updated`, `source`, `pipeline`) are mandatory at
   dataset top level — that is what makes data reusable (FAIR).

## Packaging

Datasets are wrapped in an **RO-Crate v1.1 manifest**
(`docs/data/ro-crate-metadata.jsonld`, generated by
`scripts/gen_ro_crate.py`) — the format the ELN Consortium's `.eln`
standard is built on, so the whole hub imports into eLabFTW-class tools.
Regenerate whenever datasets are added or removed.

*Part of the integration contract — see docs/research/tools-and-integration.md*
